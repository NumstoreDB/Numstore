# v1.5.1

Unreleased.

**A database that crashed could come back wrong. This release fixes that.**

Nothing about the API, the query language or the file format changed. If 1.5.0
worked for you, this is a drop-in upgrade, and it is worth taking.

## Why you would upgrade

Every problem below needed a crash (or a `pgr_crash`-style abrupt exit) to show
up. On a clean `close()` 1.5.0 was fine. But if a process died mid-write:

- **A fresh database could fail to open.** Creating a database and immediately
  reopening it could fail outright.
- **Reopening could lose committed data.** Work that `commit()` had already
  reported as durable could be missing after a crash and reopen, because pages
  the recovery pass had rebuilt were dropped before they reached disk.
- **Crashing twice could corrupt the file.** A second crash before a clean
  close could leave the log describing records that were not there, and the
  database would come back with some changes applied and others not. Reading a
  variable could then fail with a checksum or page-type error.
- **Rolling back could silently not stick.** A `rollback()` looked right in the
  same session but could be partly forgotten after a close and reopen.

After this release, a crash at any point leaves you with exactly the committed
state - which is what the durability guarantee was always supposed to mean.

## If you were working around this

You can stop. Specifically:

- No need to `close()` defensively before anything risky.
- No need to treat a database that has been through a crash as suspect.
- `samples/sample4_crash.py` is the shortest demonstration that it holds.

## Also in this release

- The repository was reorganised (`libs/numstore`, `libs/pynumstore`), and the
  documentation reorganised with it. `#include "numstore.h"` is unchanged, the
  wheel contents are unchanged, and `pip install pynumstore` is unaffected.
- A gRPC server and client landed as a skeleton under `libs/nsserver` and
  `apps/`. It is not wired to numstore yet and does not affect the library -
  see [The numstore RPC](../rpc.md).

Internals, file by file, are in
[CHANGELOG.md](https://github.com/NumstoreDB/Numstore/blob/develop/CHANGELOG.md).
